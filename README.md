# Анализ разности фаз каналов USRP X310 (4 приёмных канала)

Пакет MATLAB-скриптов для поиска закономерности в разности фаз между
каналами при приёме общего тона через разветвитель (fc + fd → тон fd на выходе).

## Имена файлов (нейминг v2 — fd может быть отрицательным)

    data_<DDMMHH>_<f>_<fd>.bin,  fd ∈ {…, -13, -10, -5, 5, 10, 13, …}

`<fd>` записывается **со знаком**: `data_190914_1000_-5.bin` — тон на
−5 МГц (спектральная компонента на отрицательной частоте),
`data_180918_1000_5.bin` — на +5 МГц. Знак `+` тоже принимается
(`data_181018_1000_+5.bin` эквивалентно `_5.bin`). Анализатор разбирает
оба варианта и учитывает знак во всех расчётах.

## Физика задачи

Если на все 4 канала через разветвитель подаётся синусоида fc + fd, а приём
идёт на несущей fc, то на выходе каждого канала будет тон fd, но с разной
фазой. Две модели (обе реализованы в анализаторе):

1. **M2 (чистая задержка)** — канал k стартует с постоянной задержкой τ_k:
       φ_k = φ_0 − 2π·fd·τ_k  →  Δφ_kj = −2π·fd·(τ_k − τ_j),
   Δφ линейна по fd (со знаком) и не зависит от fc. Наклон прямой =
   межканальная задержка. Это идеальная модель; на синтетических
   testdata она выполняется точно.
2. **M3 (офсет + задержка)** — реальные данные (сеанс 251126, 6 несущих)
   показали: помимо задержки каждый канал имеет **офсет C_k(fc)** —
   постоянный сдвиг фазы на данной несущей, который НЕ растёт с fd:
       Δφ_k(fd, fc) = C_k(fc) − 0.36·fd[МГц]·Δτ_k[нс].
   Офсет меняется при перенастройке fc (скачками), но воспроизводится
   при возврате на ту же fc (≤1,4° за 6 дней) — т.е. это свойство
   тракта (LO/смеситель/DDC), пригодное для статической калибровочной
   таблицы. Чисто задержечная модель M2 на таких данных даёт невязку
   ~100° при шуме измерения ~0,01° — анализатор это детектирует и
   предупреждает.

Компенсация канала (выравнивание к ch0 — синхронно и синфазно) по M3:

    x_k  ←  x_k · exp(−j·(C_k(fc) − 0.36·f·Δτ_k)),   f — МГц от fc.

Для широкополосного сигнала задержечная часть (линейный по f член)
выравнивает и время, офсетная — фазу; модель валидна в полосе снятых |fd|.

Важно про неоднозначность: Δφ измеряется по модулю 360°, поэтому часть
параметров неразличима. У M3 (офсеты свободны) период неоднозначности
Δτ равен 1000/НОД(разностей fd **внутри одной fc**); у M2 (офсета нет) —
шире: 1000/НОД(|fd|) по всем точкам. Для полной пары ±fd период M3
равен 500/|fd| (та же величина, что у формулы пары
ΔΣ = −(Δφ₊−Δφ₋)/(0.72·fd)). Если все |fd| кратны 5 МГц — задержка M3
известна с точностью до 200 нс. Для однозначности нужны взаимно простые
|fd| (например, 7 и 13 МГц) — скрипт сам печатает период и предупреждает.

## Как пользоваться

### Скрипт 3 — просмотр одной записи
```matlab
cd matlab
plot_iq_capture            % читает pelengator_iq_capture.bin из ../upload
```
Настройки в начале скрипта: `File` (имя/путь файла), `NPlot` (сколько
отсчётов показывать), `SavePng`. Открывает 4 окна: осциллограммы I/Q всех
каналов, спектры, годографы IQ, огибающие.

### Скрипт 4 — анализ серии data_<time>_<f>_<fd>.bin
```matlab
cd matlab
analyze_phase_diffs                  % DataDir = '../testdata' по умолчанию
% или с переопределением настроек (без правки файла):
analyze_phase_diffs(struct('DataDir', 'D:\measurements', 'SNRMin', 15))
```
Настройки (в блоке НАСТРОЙКИ или через структуру-аргумент): `DataDir` —
папка с файлами; `SNRMin` — порог SNR тона (дБ); `MakeFigures` — false для
расчёта без графиков (headless); `SaveCsv`/`SaveMat`/`SavePng` — выгрузка.

Что выдаёт скрипт 4:
- консольная таблица: Δφ(k−1) каждого файла + SNR + отметка «тон не обнаружен»;
- фиты M1/M2/M3 по каждому каналу (все записи с тоном совместно): Δτ(M2),
  Δτ(M3) и офсеты C_k(fc) с СКО невязок, периоды неоднозначности,
  предупреждения о наборе fd (нет пар ±fd, одно значение fd на fc,
  мало избыточности) и о неадекватности M2 (невязка на порядок выше
  шума измерения — доминирует офсет, Δτ(M2) не является задержкой);
- калибровочная таблица (fc, C_k, Δτ_k) и формула компенсации;
- окно 1: теплокарты матриц Δφ 4×4 (φ_i − φ_j) по каждому файлу;
- окно 2: (а) столбцы Δφ(k−1) по файлам; (б) Δφ от fd — точки и линии
  совместного фита M3 (пунктир, по каждой fc); (в) Δτ по каждому файлу
  отдельно + горизонтальные линии совместной Δτ(M3);
- `phase_diff_results.csv` (формат прежний: по строке на файл),
  `phase_diff_calibration.csv` (по строке на (канал, fc): C, Δτ,
  неоднозначности M3/M2, СКО невязок M2/M3, шум, флаги разделимости и
  адекватности) и `phase_diff_results.mat` (все фиты) в папке данных.

| 10 | −49.3° | −148.3° | 43.6° |

- Δφ от fc не зависит (файлы 1000_10 и 900_10 дают идентичные Δφ) —
  подтверждает гипотезу постоянных задержек старта каналов;
- **нечётность по знаку**: Δφ(−fd) = −Δφ(fd) с точностью 0.07°
  (например, fd=−5 → +24.7° против fd=+5 → −24.6°) — знак fd из имени
  файла корректно учтён во всём тракте;
- восстановленные Δτ = 13.70 / 41.20 / 87.90 нс (M3 = M2, офсеты ≈ 0°,
  СКО невязки < 0.03°, период неоднозначности 1000 нс при НОД = 1 МГц
  из-за взаимно простых 13 и 5);
- ошибка восстановления Δφ < 0.05° при SNR 62 дБ.

## Проверка на реальных данных (сеанс 251126, 36 файлов, 6 несущих 700–1200 МГц, пары ±fd)

M3-фит (совместный по всем fc) воспроизводится анализатором с точностью
< 0,01 нс / 0,3° относительно независимо сделанного эталонного расчёта:

- Δτ = +1.11 / +0.18 / +1.48 нс (ch1/ch2/ch3; общие на все fc),
  СКО невязки 2.5 / 1.0 / 4.1 град (квадратичная систематика в полосе);
- офсеты C_k(fc) — калибровочная таблица (см. отчёт, таблица 6);
- M2 на этих данных даёт +42.4 нс при невязке 99.8° (шум 0.01°) —
  анализатор печатает предупреждение о неадекватности;
- период неоднозначности M3 = M2 = 200 нс (НОД |fd| = 5 МГц).

## Про реальный файл pelengator_iq_capture.bin

В выложенном примере **тона нет** — запись шумоподобная (SNR пика ≈ 5 дБ,
«пик» спектра скачет по частоте от сегмента к сегменту). Обнаружен общий
широкополосный компонент в каналах (когерентность 0.13–0.19; фаза
кросс-спектра пары ch0–ch1 плоская ≈ 90° по всей полосе — это похоже на
наводку/общий шум тракта, а не на полезный сигнал). Поэтому оба скрипта
детектируют отсутствие тона (порог SNRMin = 20 дБ) и помечают такие файлы,
чтобы Δφ по ним не принимались за калибровку. Для реальной калибровки
запишите файлы с поданным через разветвитель тоном fc + fd.

## Совместимость

Скрипты проверены в GNU Octave 9.4 и написаны в подмножестве MATLAB:
без тулбоксов (Signal/DSP не нужны), локальные окна Ханна/FFT-оси
реализованы внутри. В MATLAB R2016b+ работают без изменений.
